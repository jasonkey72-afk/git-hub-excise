초기 구축 · STEP 1

① Windows에 Git 설치하기

VS Code보다 먼저 해야 합니다. Git 프로그램 자체가 PC에 설치되어 있어야 VS Code도 Git 기능을 사용할 수 있습니다.

초보자 핵심

GitHub = 웹 서비스이고, Git = 내 PC에 설치하는 프로그램입니다. GitHub 계정만 있다고 VS Code에서 Git이 바로 동작하는 것은 아닙니다.

1
공식 Git 사이트 접속

git-scm.com → Download for Windows

2
Windows 설치파일 실행

회사 PC라면 보안정책/관리자 권한 여부를 먼저 확인합니다.

3
초보자는 설치 옵션을 임의로 바꾸지 말고 기본값 중심으로 진행

특별한 사내 표준이 없다면 기본 설정을 유지합니다.

4
설치 완료 후 VS Code를 완전히 종료했다가 다시 실행

설치 전 열려 있던 VS Code가 새 Git 경로를 바로 인식하지 못할 수 있으므로 재실행이 안전합니다.

설치됐는지 딱 한 줄로 확인

git --version

Enter 후 git version ...이 보이면 설치 성공입니다.

✅ 정상

git version 2.x.x.windows.x

Git 명령을 사용할 준비가 됐습니다.

❌ 인식 안 됨

'git' is not recognized...

Git 미설치 또는 PATH 인식 문제입니다. 설치 후 VS Code/터미널을 재시작합니다.

기억: GitHub 가입보다 먼저가 아니라, VS Code에서 Git을 쓰기 전에 Git 설치가 먼저입니다.
초기 구축 · STEP 2

② VS Code에서 Git 사용 준비하기

일반적인 Git 작업에는 별도 Git 확장 프로그램 설치가 필요하지 않습니다. VS Code의 Git 지원은 기본 내장이며, PC에 설치된 Git을 사용합니다.

✅ 반드시 필요한 것

PC에 Git 설치

VS Code가 이 Git 실행파일을 사용합니다.

🧩 별도 확장 설치?

기본 Git 사용: 필요 없음

Source Control, Stage, Commit, Branch, Push/Pull은 VS Code 기본 기능으로 사용할 수 있습니다.

VS Code에서 확인 순서

VS Code 재실행

01 · 가장 먼저

Git과 GitHub는 같은 것이 아닙니다

📚 Git

내 PC의 버전관리

파일 변경을 기록하고 Branch를 관리합니다. 아래 명령은 한꺼번에 실행하는 예제가 아니라 각각 서로 다른 역할을 가진 명령입니다.

예: Git 저장소 시작
git init
→ “이 폴더에서 Git 관리를 시작해 줘.”
예: 파일을 다음 저장 대상으로 선택
git add 파일명
→ “이 파일을 다음 Commit에 포함해 줘.”

☁️ GitHub

인터넷의 저장·협업 공간

Local Git의 Commit과 Branch를 원격 Repository에 공유합니다.

예: GitHub로 보내기
git push
→ “Local에 저장된 Commit을 GitHub로 보내 줘.”
예: GitHub 내용 가져오기
git pull
→ “GitHub의 최신 내용을 내 PC로 가져와 줘.”
⭐ 핵심: 이 교재의 모든 명령은 한 줄 입력 → Enter → 결과 확인 → 다음 명령 순서로 실행합니다. Commit했다고 GitHub에 올라간 것도 아닙니다.

GitHub Repository 정확한 주소 확인하기

STEP 1 · GitHub에서 복사

GitHub에서 올릴 Repository로 들어갑니다.
파일 목록 위쪽의 <> Code 버튼을 클릭합니다.

https://github.com/jasonkey72-afk/git_study.git
→ 이런 형태의 주소가 Git 연결용 Repository 주소입니다.

STEP 2 · VS Code에서 현재 주소 확인

한 줄 입력 후 Enter
git remote -v
→ 현재 Local 프로젝트가 어느 GitHub Repository로 연결되어 있는지 확인합니다.
주소가 다르면 한 줄 입력 후 Enter
git remote set-url origin <복사한 HTTPS 주소>
→ origin의 목적지를 정확한 Repository 주소로 바꿉니다.
초보자 원칙: Repository 주소는 기억해서 입력하지 않습니다. GitHub의 <> Code → HTTPS → 복사로 가져옵니다.

오류가 나오면 명령을 반복하지 말고, 먼저 git status, git branch, git remote -v로 현재 상태를 확인합니다.

10 · 오류 실전 #1

git_study.html만 GitHub에 올린다면

아래는 6개 명령을 한 번에 실행하는 것이 아닙니다. 반드시 STEP별로 한 줄씩 실행하고 결과를 확인합니다.

STEP 1 · 폴더 이동
cd /c/Python/company/git_test
→ git_study.html이 있는 폴더로 이동
STEP 2 · Git 시작 (처음 한 번만)
git init
→ 이미 Git 저장소라면 다시 할 필요 없음
STEP 3 · 이 파일만 선택
git add git_study.html
→ 다른 파일이 아니라 git_study.html만 다음 Commit 대상으로 선택
STEP 4 · Local에 저장
git commit -m "git_study 최초 등록"
→ 내 PC의 Git에 하나의 버전으로 저장
STEP 5 · GitHub 목적지 연결 (처음 한 번만)
git remote add origin <GitHub HTTPS URL>
→ GitHub Repository를 만드는 명령이 아니라 주소를 등록하는 명령
STEP 6 · GitHub로 전송
git push -u origin main
→ Local main의 Commit을 GitHub로 보냄
이미 Commit되어 있고 working tree clean이라면 STEP 3·4를 다시 하지 않습니다. 목적지 연결도 이미 되어 있다면 STEP 5를 다시 하지 않습니다.

12 · 오류 실전 #3

src refspec ... does not match any

원인 A

Push하려는 Branch가 Local에 없음.

먼저 확인
git branch
→ feature/signup이 없다면 다음 명령
git switch -c feature/signup

원인 B

최초 저장소인데 아직 Commit 자체가 없음.

먼저 파일 선택
git add .
Enter → 그 다음
git commit -m "first commit"
Git에게 “feature/signup을 보내”라고 했는데 Local에서 그 이름/Commit을 찾지 못한 상황입니다.
13 · 오류 실전 #4

Repository not found

Local origin
→
주소 오타 / Repo 없음
또는 접근권한 문제
git remote -v

GitHub에서 실제 Repository가 존재하는지, <> Code → HTTPS 주소와 일치하는지 확인합니다.

git remote set-url origin <복사한 정확한 URL>
중요: git remote add origin ...은 GitHub Repository를 “생성”하지 않습니다. Local에 목적지 주소를 등록할 뿐입니다.
14 · VS Code 실전 루틴

Updates were rejected because the remote contains work...

LOCAL

git_study.html Commit

●

GITHUB

README 등 별도 Commit

●
둘이 서로 다른 시작 이력을 가지면 Push가 거절될 수 있습니다. 기존 Local 프로젝트를 처음 올릴 때 GitHub의 새 Repository를 README / License / .gitignore 없이 빈 저장소로 만들면 가장 단순합니다.
STEP 1 · GitHub 이력을 Local로 가져와 합치기
git pull origin main --allow-unrelated-histories
→ Enter 후 결과를 확인합니다. 충돌이 있으면 해결이 먼저입니다.
STEP 2 · 합치기가 정상 완료된 뒤에만 Push
git push -u origin main
→ STEP 1이 성공한 것을 확인한 후 별도로 실행합니다.

⚠️ 초보 실습에서는 무작정 git push --force를 사용하지 않습니다.

16 · 한 장 요약

Git 초보자의 생존 공식

① Local ≠ GitHub

Branch/Commit은 먼저 내 PC에 존재할 수 있다.

② Commit ≠ Push

Commit은 Local 저장, Push는 Remote 전달.

③ origin = 목적지

git remote -v로 Repository 확인.

④ * = 현재 Branch

git branch로 작업 위치 확인.

⑤ U/M/A는 상태표시등

파일이 어느 단계인지 알려준다.

⑥ 막히면 status

git status가 가장 먼저 볼 진단 화면.

외우지 마세요. “Local인가? Remote인가? 파일인가? Commit인가? Branch인가?”만 구분하면 대부분의 Git 오류가 읽히기 시작합니다.
실전 오류 · 자주 하는 실수

🚨 Repository 주소가 다르면 Push가 안 됩니다

Branch가 정상이어도 origin이 잘못된 GitHub Repository를 가리키면 Repository not found가 발생합니다.

❌ Local Git이 기억하고 있던 주소

git remote -v
origin  https://github.com/jasonkey72-afk/git_study.git (fetch)
origin  https://github.com/jasonkey72-afk/git_study.git (push)

✅ GitHub에서 실제 확인한 주소

https://github.com/jasonkey72-afk/git-hub-excise.git

두 주소의 Repository 이름이 다릅니다.

Local
lecture
→
origin
git_study
→
GitHub
없음/다름
그래서 발생한 오류
remote: Repository not found.
fatal: repository '.../git_study.git/' not found

이 경우 lecture Branch가 문제인 것이 아닙니다. 목적지 Repository 주소가 틀린 것입니다.

초보자용 해결 순서 — 한 줄씩 실행하세요

1
GitHub에서 정확한 주소 복사

Repository → <> Code → HTTPS → 복사

2
현재 Local 주소 확인
git remote -v

Enter → GitHub에서 복사한 주소와 비교

3
다르면 origin 주소 수정
git remote set-url origin https://github.com/jasonkey72-afk/git-hub-excise.git

Enter

4
다시 확인
git remote -v

Enter → 두 줄 모두 git-hub-excise.git인지 확인

5
현재 Branch를 Push
git push -u origin lecture

Enter

💡 기억 공식

git branch = 어느 Branch?   /   git remote -v = 어느 Repository?

Push 전에 이 두 가지를 확인하면 초보자가 하는 실수를 크게 줄일 수 있습니다.
