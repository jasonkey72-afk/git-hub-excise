1a2f6d docs: 왜 GitEasy가 필요한가

"pull이 뭔데 안 되는 거예요?"

Git은 원래 개발자를 위해 만들어진 도구입니다. 그래서 검은 콘솔창, 영어 오류 메시지, 외워야 하는 명령어가 기본값이죠. 기획·마케팅·운영 등 코드를 매일 다루지 않는 분들에게는 이 장벽 자체가 협업을 가로막는 벽이 됩니다.

기존 방식 — Git Bash
  • git pull origin main — 정확한 철자와 순서를 외워야 함
  • 영어로 된 오류 메시지 앞에서 멈춰버림
  • "브랜치"가 뭔지, 내가 지금 뭘 누른 건지 알 수 없음
  • 잘못 누르면 되돌릴 수 있는지조차 불안함
GitEasy 방식
  • 버튼에 이미 한글 이름이 적혀 있음 — Pull (스마트)
  • 오류가 나면 원인과 해결법을 바로 보여주는 팝업
  • 버튼에 마우스를 올리면 무슨 뜻인지 말풍선으로 설명
  • 위험한 작업은 실행 전 한 번 더 확인 후 진행
7c3b91 docs: Git이 뭔가요

한 줄로 설명하면, "무한 되돌리기 저장소"

한글 문서를 "최종", "최종_진짜", "최종_진짜진짜"로 저장해본 적 있다면, 이미 Git이 하는 일의 절반은 이해하신 겁니다.

①

Git

파일이 바뀔 때마다 "이 시점"을 스냅샷처럼 저장해두는 기록 시스템. 언제든 예전 버전으로 되돌아갈 수 있습니다.

②

커밋(Commit)

"여기까지 작업한 내용을 하나로 묶어서 저장"하는 행위. 저장할 때마다 짧은 메모(커밋 메시지)를 남깁니다.

③

GitHub

그 기록들을 인터넷 서버에 올려서, 팀원 누구나 최신 버전을 받아보고 함께 작업할 수 있게 하는 창고입니다.

④

브랜치(Branch)

원본은 그대로 두고, 별도의 작업 공간을 하나 더 만드는 것. 실험하다 실패해도 원본은 안전합니다.

GitEasy는 4가지 원칙으로 만들어졌습니다.

🖱️

전부 버튼으로

저장·업로드·내려받기 등 실제 업무에 필요한 모든 동작을 한글 버튼으로 제공합니다.

⚡

알아서 처리

"이럴 땐 이렇게"가 필요한 상황(충돌 위험, 업로드 거부 등)을 자동으로 감지해 안전하게 처리합니다.

💬

마우스만 올려도 설명

모든 버튼에 말풍선 설명이 붙어있고, Git 명령어 사전도 클릭 한 번으로 열립니다.

🩺

오류가 나도 당황 없이

오류가 발생하면 원문 복사 + 원인 진단 + 해결법을 한 화면에서 바로 보여줍니다.

b83c07 feat: 처음 시작하기 5단계

첫 작업, 5단계면 끝

아래 단계를 순서대로 눌러보세요. 실제로 작업할 때도 이 순서 그대로 따라가면 됩니다.

1. 저장소 열기

처음이라면 복제(Clone)를 눌러 GitHub 저장소 주소(URL)를 입력하고 저장 위치를 고릅니다. 이미 받아둔 폴더가 있다면 폴더 열기로 선택하세요.

📁 폴더 열기 / 복제(Clone)

2. 평소처럼 파일 수정

엑셀, 문서, 코드 등 저장소 폴더 안의 파일을 평소 쓰던 프로그램으로 열어 수정하고 저장합니다. GitEasy는 계속 켜둔 채로 두어도 됩니다.

✏️ 특별한 조작 없음

3. 바뀐 파일 Add 하기

왼쪽 "변경된 파일" 목록에 방금 수정한 파일이 자동으로 나타납니다. 체크 후 선택 Add →, 전부 다 올릴 거면 전체 Add를 누릅니다.

☑️ 선택 Add → / 전체 Add

4. 메시지를 남기고 Commit

하단 입력창에 "무엇을 바꿨는지" 한 줄로 적습니다. 예: "3분기 실적표 수정". 그다음 커밋을 누르면 이 시점이 기록으로 남습니다.

📝 커밋

5. GitHub로 Push

Push (스마트)를 누르면 내 기록이 GitHub에 올라갑니다. 팀원의 작업이 먼저 올라가 있어도 자동으로 받아온 뒤 다시 시도하니 걱정 없습니다.

🚀 Push (스마트)

💡 더 빠른 방법 — 3~5단계가 귀찮다면, 메시지만 입력창에 써두고 🔄 Sync 버튼 하나만 누르세요. Pull → Add → Commit → Push가 순서대로 자동 실행됩니다.

2ad9f4 feat: 스마트 자동화 4가지

"이럴 땐, 이것을" — 알아서 처리되는 것들

GitEasy가 뒤에서 자동으로 판단하고 처리해주는 4가지 상황입니다.

🗂️

Pull 전 자동 보관

저장 안 된 변경사항이 있는 채로 Pull을 누르면, 자동으로 잠깐 따로 보관(stash)해두고 최신 내용을 받은 뒤 다시 복원합니다.

🔁

Push 거부 시 자동 재시도

팀원이 먼저 올린 내용이 있어 Push가 거부되면, 자동으로 먼저 Pull한 뒤 다시 Push를 시도합니다.

⚠️

충돌 감지 & 안내

같은 부분을 서로 다르게 고쳐 충돌이 나면, 어떤 파일에서 문제가 생겼는지 콕 집어 화면에 보여줍니다.

🔄

Sync 원클릭

Pull → Add → Commit → Push, 4단계를 순서 그대로 한 번에 실행하는 버튼입니다. 익숙해지면 이것 하나만 눌러도 됩니다.

더 궁금한 용어 살펴보기

커밋(Commit)이 뭔가요? +
"여기까지 작업한 내용을 하나로 묶어서 저장"하는 행위입니다. 저장할 때마다 무엇을 바꿨는지 짧은 메모(커밋 메시지)를 함께 남깁니다.
브랜치(Branch)가 뭔가요? +
원본(주로 main)은 그대로 두고 별도의 작업 공간을 하나 더 만드는 기능입니다. 화면 상단 브랜치 메뉴에서 선택할 수 있고, (원격 전용)이라고 표시된 항목은 아직 내 컴퓨터엔 없고 GitHub에만 있는 브랜치입니다 — 선택하면 자동으로 받아옵니다.
충돌(Conflict)이 뭔가요? +
같은 파일의 같은 부분을 나와 다른 사람이 서로 다르게 고쳤을 때, Git이 어느 쪽을 남길지 스스로 정하지 못하는 상태입니다. 파일을 열어 표시된 부분을 직접 정리한 뒤 다시 Add·커밋하면 해결됩니다.
스테이징(Staging)이 뭔가요? +
저장(커밋)하기 전에 "이번엔 이 파일들을 저장할게요"라고 미리 담아두는 단계입니다. GitEasy에서는 이 단계가 Add 버튼입니다.
Git 콘솔창은 언제 쓰나요? +
오른쪽 아래 입력창에 git을 빼고 명령어만 입력하면(예: log --oneline -5) 직접 실행할 수 있습니다. ↑ / ↓ 키로 이전 명령을 다시 불러올 수 있어 조금 더 익숙해진 뒤 활용하면 좋습니다.
d47c19 docs: 자주 묻는 질문

자주 묻는 질문

교육 중 가장 많이 나온 질문들을 모았습니다.

실수로 아무 버튼이나 눌렀어요. 되돌릴 수 있나요? +
대부분의 버튼은 안전합니다. 파일을 지우거나 되돌리기 어려운 명령(예: --hard, --force, clean)을 콘솔창에서 직접 입력할 때만 "정말 실행할까요?" 확인창이 한 번 더 뜹니다. 그 외 Add·커밋·Push는 데이터를 삭제하지 않으니 편하게 눌러보셔도 됩니다.
브랜치가 뭔지 몰라도 써도 되나요? +
네, 대부분의 업무는 main 브랜치 하나만으로 충분합니다. 브랜치는 여러 사람이 동시에 다른 실험을 진행할 때 필요한 개념이니, 필요해지면 그때 "용어 사전" 섹션을 다시 참고하세요.
충돌이 났는데 혼자 해결 못 하겠어요. +
오류 도우미 창에서 📋 오류 내용 복사를 눌러 내용을 복사한 뒤, 충돌난 파일 목록과 함께 담당자나 팀 채널에 붙여넣어 공유해주세요. 화면만 보여줘도 어디서 문제가 생겼는지 바로 파악할 수 있습니다.
인터넷이 없어도 쓸 수 있나요? +
파일 수정, Add, Commit(내 컴퓨터에 기록 저장)까지는 인터넷 없이도 가능합니다. 다만 Push·Pull·Fetch처럼 GitHub와 주고받는 동작은 인터넷 연결이 필요합니다.
Git이 컴퓨터에 설치되어 있어야 하나요? +
네. GitEasy는 화면(UI)만 제공하고, 실제 작업은 컴퓨터에 설치된 Git 프로그램을 통해 이뤄집니다. 처음 설치 시 IT 담당 부서의 안내에 따라 Git이 함께 설치되어 있는지 확인해주세요.
